## 1. 项目概述

### 1.1 一句话描述

一张带**障碍物的大地图**上，蓝（玩家）红（AI）各拥一座主堡；
玩家**点击底部卡牌消耗金币出兵**（单位在城堡前集结），用**经典 RTS 操作**指挥部队
（右键点选、框选、左键移动、A+左键攻击移动）；
**AI 用状态机**决策「集结 → 全面进攻」；率先摧毁敌方主堡获胜。

### 1.2 定位要点

- **卡牌是生产方式**：点卡 = 出兵，玩家不建建筑、不造兵营，操作集中在「出兵时机 + 部队指挥」。
- **RTS 是玩法内核**：大地图、障碍物、寻路、框选指挥、攻防决策 —— 战略手感完整。
- **AI 是状态机**：MVP「集结 → 全面进攻」，架构预留战术扩展（侦察/巡逻/钳形攻势，未来可接大模型）。
- **规模导向**：渲染/逻辑/性能按 **500+ 单位**设计，MVP 先跑 100~150 验证。

### 1.3 设计原则

1. **点卡即出兵**：点击卡牌单位即在城堡前集结，操作零门槛。
2. **经典 RTS 手感**：点选/框选/移动/攻击移动直觉化，后续可扩展更多命令。
3. **寻路可靠**：障碍物 + A* + 防卡机制，单位绝不长时间卡死。
4. **AI 状态机化**：敌方决策 = 可扩展状态机，状态与转移条件全部数据化。
5. **数据驱动**：兵种/卡牌/障碍物布局/AI 参数全部配置化，加内容不改逻辑。
6. **内核与渲染解耦**：纯 TS 内核（寻路/AI/战斗）不依赖 Phaser，为联机/回放/AI 对 AI 留接口。

### 1.4 范围（MVP / 后续）

| 范围 | MVP（M1） | 后续（M2/M3） |
|---|---|---|
| 地图 | 大地图 + 障碍物（树林/岩石）+ 主堡 | 河流/桥梁、金矿、迷雾、动态地形 |
| 玩法 | 金币、卡牌出兵、集结/集结点、RTS 指挥、胜负 | 团卡、限时模式、据点制 |
| 单位 | 长枪兵 / 剑士 2 张卡 | 弓箭手/骑兵/肉盾、克制表 |
| 指挥 | 点选、框选、移动、攻击移动、集结点 | 编队快捷键、巡逻、更多命令 |
| 寻路 | A* + 局部避让 + 防卡 | 编队寻路优化、动态避障 |
| AI | 状态机「集结→全面进攻」 | 侦察/巡逻/钳形攻势、LLM 融合、难度档 |
| 规模 | 同屏 100~150 单位 | 500+ 单位性能达标 |

## 2. 名词表

| 名词 | 说明 |
|---|---|
| 阵营（Team） | `blue`（玩家）/ `red`（AI），与兵种解耦 |
| 主堡（Castle） | 双方核心建筑，有 HP，被摧毁即分出胜负；自带**集结点**功能 |
| 集结（Gather） | 单位出生后在城堡前/集结点停留待命的状态 |
| 集结点（Rally Point） | 玩家为主堡设定的"新兵集结位置"；未设置则默认城堡门前 |
| 卡牌（Card） | 底部卡牌栏中的卡片，点击即消耗金币出兵 |
| 出兵（Deploy） | 点击卡牌 → 扣金币 → 单位在城堡门前生成 → 自动前往集结点 |
| 框选（Box Select） | 拖拽拉框选中框内己方单位 |
| 攻击移动（Attack-Move） | A + 左键：沿路前进，途中自动攻击遇到的敌人，清完后继续前进到目标点 |
| 移动（Move） | 左键：寻路前往目标点，途中不主动接敌（被攻击时还手）|
| 待命防御（Hold/Defend） | 单位在集结点的默认行为：索敌半径内敌人自动交战，不追击出范围 |
| 自动寻路（Pathfinding） | 网格 A* + 路径跟随 + 局部避让 + 防卡重寻 |
| 状态机（State Machine） | 个体单位与敌方 AI 都用状态机表达行为与决策 |
| 指令模式（Command Mode） | 按 A 后进入"攻击移动"待命指令状态（光标/提示变化）|
| LOD（Level of Detail） | 按缩放级别切换单位呈现：小点 → 剪影 → 精细动画 |
| 空间网格（Spatial Grid） | 按格索引单位，索敌从 O(n²) 降到邻域查询 |

## 3. 游戏流程

### 3.1 整体流程

```
进入对局（MVP 直接开局，无主菜单；P1 加主菜单/难度选择）
   ↓
对局进行（见 3.2）
   ↓
一方主堡 HP ≤ 0 → 结算画面（胜利/失败 + 统计）
   ↓
「再来一局」→ 完整重置（金币、单位、主堡 HP、AI 状态机、集结点）→ 重新开局
```

- **重开**：清空所有单位/特效/指令，金币恢复 100，主堡满血，AI 回 IDLE；比分/胜场记录（P2）。
- **暂停**：P1 加（空格键 + 暂停面板）。

### 3.2 对局内时序（节奏预期）

| 阶段 | 时间（约） | 双方行为 | 玩家关注点 |
|---|---|---|---|
| 开局 | 0~30s | AI 处于 IDLE（4s）后开始出兵集结；玩家点卡攒兵 | 攒第一波兵、设集结点 |
| 运营 | 30s~2min | 双方出兵集结、试探性接触 | 兵力分配、是否提前骚扰 |
| 决战 | 2min~结束 | AI 兵力达阈值发起全面进攻；玩家防守/反打 | 攻防转换、一波定胜负 |
| 结束 | 主堡被摧毁 | 结算 | - |

> 节奏由数值决定（见第 7 节），预期一局 3~6 分钟，可调。

## 4. 核心玩法循环（双循环）

```
━━━━ 经济循环 ━━━━
金币 20/s 自动增长 → 点卡出兵（60/100）→ 单位城堡前集结 → 待命防御
                        ▲                          │
                        └── 出兵越多 → 防御越稳 ────┘

━━━━ 军事循环 ━━━━
玩家指挥（移动/攻击移动/集结点）→ 部队推进 → 遭遇战（自动交战）
        → 兵力占优 → 围攻敌方主堡 → 摧毁 → 胜利
        （失败路径：被 AI 全面进攻摧毁主堡）
```

## 5. 功能需求详述

### 5.1 战场与地形

**F1. 地图规格**
- 世界尺寸 **4800 × 3200**（可调，约为屏幕可视面积的 15 倍）；默认缩放下单位只有十几像素。
- 地图背景：草地色块 + 道路（连接双方主堡的视觉路径）+ 边界（不可通行）。

**F2. 障碍物（MVP 必须有）**
- **树林**：5~8 簇（每簇 3~6 棵树冠），**不可通行**；布置在中央与两翼，形成绕行路线与战场分割。
- **岩石**：8~12 块零散巨石，不可通行；可与树林搭配出窄口。
- **布局约束**：
  - 双方主堡之间**至少 2~3 条可行通路**（中路 + 两翼），不出现必死堵局；
  - 障碍物基本对称，不偏袒任一方；
  - 布局数据化（坐标列表，`src/core/mapLayout.ts`），便于调整与未来随机生成（P2）。
- 草丛/色块：纯装饰。

**F3. 可通行性模型**
- 地图按 **64px 网格**栅格化：障碍物占格 = `不可走`，其余可走（河流等将来接入同一模型）。
- 渲染用障碍物，寻路用网格 —— 两套数据同源生成，避免不一致。

**F4. 地形渲染**
- 地形一次性绘制到离屏 `RenderTexture`，相机平移缩放不再逐帧重画（帧预算留给单位）。

### 5.2 相机、缩放与小地图

**F5. 缩放**
- 滚轮缩放范围 **0.2× ~ 3.0×**：全图俯瞰 → 默认视野（单位=小点+阵营椭圆）→ 放大看精细动画。
- **以鼠标指针为中心**，平滑缓动（约 0.1~0.2s）。

**F6. 平移**
- 中键按住拖拽 + WASD/方向键；相机限制在地图边界内。

**F7. 小地图**
- 右上角固定（约 240×160）：地形 + 障碍物 + 双方主堡 + 单位（阵营色小点）。
- 点击/拖拽 → 相机跳转。大地图 + 500 单位下的全局掌控必需。

### 5.3 主堡与集结点

**F8. 主堡**
- 大型代码绘制建筑（塔楼+城墙+阵营旗帜），约 260×300；HP **3000** 双方相同，顶部 HUD 两侧显示。
- 主堡是**可被攻击目标**（复用武器几何攻击；单位抵近约 200px 即攻击，有固定"目标中心"）。
- MVP：主堡**被动挨打**；P1 可选自卫反击（射程内周期性射击）。

**F9. 集结点（主堡功能）**
- 设置：**选中己方主堡 → 左键点击地图任意可走位置** → 设置/移动集结点（地图上显示己方阵营色旗帜）。
- 效果：新出的兵在城堡门前生成后**自动寻路走向集结点**集结；未设置则默认城堡门前待命。
- 主堡被摧毁后集结点标记消失。

**F10. 胜负判定**
- 任一主堡 HP ≤ 0 → 立即结算（玩家摧毁红堡=胜利；蓝堡被摧毁=失败）。
- 结算画面：遮罩 + 「胜利/失败」+ 统计（用时/出兵数/击杀数，MVP 先做用时与出兵数）+「再来一局」。
- P2：限时模式 / 据点制胜利。

### 5.4 经济与卡牌

**F11. 经济**
- 金币 **20/s** 自动增长（用户指定），开局 **100**，无上限；顶部实时显示。

**F12. 卡牌栏**
- 屏幕底部固定居中（`scrollFactor: 0`）：**长枪兵（60 金）**、**剑士（100 金）**（用户指定费用）。
- 卡片显示：兵种图标（迷你剪影）、名称、费用数字；金币不足 → 置灰不可点。
- MVP 每张卡出 **1 个单位**；P1 团卡（注册表加 `squadSize`，如「长枪兵 ×3」）为大规模铺路。

**F13. 出兵（点击即出兵）**
- 左键点击卡牌 → 校验金币 → 扣费 → 单位在**己方城堡门前**生成（尘土 + 名称飘字）→ 自动前往集结点。
- **出兵冷却 0.6s**（防连点爆兵）；单位上限 MVP 每方 **60** → M2 200 → P2 500+。
- 上限已满时点卡无效并提示「部队已满」。

**F14. 经济细节**
- 击杀不返还金币；金币只用于出兵；无其它消耗项（金矿等经济扩展为后续版本）。

### 5.5 单位系统

**F15. 兵种数据（沿用现有数值，阵营解耦）**

| 兵种 | 费用 | HP | 移速 | 伤害 | 特点（沿用现有实现） |
|---|---|---|---|---|---|
| 长枪兵 | 60 | 100 | 230 | 18 | 长枪刺击、命中击退、首击 50% 暴击(×3)、被贴脸无法出枪 |
| 剑士 | 100 | 170 | 280 | 24 | 移速快、血厚、对长枪兵 1.5 倍加成、30% 盾牌格挡弹开长枪 |

- `team` 不再是兵种属性：**召唤时指定阵营**，双方共用同一兵种池（敌我靠脚下椭圆圈区分）。

**F16. 单位个体状态机（详细规格）**

```
生成 ──→ ┌────────── GATHER（集结/待命）──────────┐
         │  · 在集结点/城堡前待命                  │
         │  · 索敌半径内出现敌人 → DEFEND          │
         │  · 收到移动/攻击移动/集火命令 → 对应状态 │
         ▼                                        │
      DEFEND（防御交战）                           │
         · 自动攻击最近敌人，不追击出索敌半径       │
         · 敌人死亡/消失 → 回 GATHER               │
         ▼                                        │
      MOVE（移动）                                │
         · 寻路前往目标点，途中不主动接敌           │
         · 被攻击 → 还手（临时 DEFEND），还完继续走 │
         · 到达 → GATHER                           │
         ▼                                        │
      ATTACK-MOVE（攻击移动）                     │
         · 沿寻路前进，途中遇敌 → 交战（同 DEFEND） │
         · 敌灭 → 回到路径继续推进 → 到达 → GATHER  │
         ▼                                        │
      ATTACK（指定集火）                          │
         · 攻击指定目标；目标死 → 换最近敌人       │
         · 无敌人 → GATHER                         │
         ▼                                        │
      DIE（死亡）→ 死亡动画 → 移除                 │
         └─────────────────────────────────────────┘
```

- 状态转移表（数据化，`core/unitStateMachine.ts`）：

| 当前状态 | 事件 | 下一状态 |
|---|---|---|
| GATHER | 索敌半径内有敌人 | DEFEND |
| GATHER | 收到 Move 命令 | MOVE |
| GATHER | 收到 Attack-Move 命令 | ATTACK-MOVE |
| GATHER | 收到集火命令 | ATTACK |
| DEFEND | 敌人死亡/逃离索敌半径 | GATHER |
| MOVE | 到达目标点 | GATHER |
| MOVE | 被攻击 | DEFEND（还手后回 MOVE）|
| ATTACK-MOVE | 途中遇敌 | DEFEND（敌灭后回 ATTACK-MOVE）|
| ATTACK-MOVE | 到达目标点 | GATHER |
| ATTACK | 目标死亡 | ATTACK（自动换最近敌人）/ 无敌人 → GATHER |
| 任意 | HP ≤ 0 | DIE |

**F17. 目标选择规则**
- 索敌/交战默认选**最近敌方单位**（沿用现有 `nearestEnemy`）；P2 可加"低血量优先"配置。
- 攻击移动中的交战不改变原目标点（打完继续走）；防御交战不追击出索敌半径。

**F18. 血条策略**
- 选中单位显示血条 + 脚下高亮圈（沿用现有）；框选多选显示数量徽标。
- 大规模时仅显示交战/受损单位血条（见 LOD，F38）。

### 5.6 单位指挥（经典 RTS 操作）

**F19. 选择**
- **右键点选**单位（用户指定）；`Shift+右键` 追加选中。
- **左键点击己方单位**：选中（与"左键空地=移动"并存，点单位=选、点空地=命令）。
- **左键拖拽框选**：拉框选中框内己方单位。
- `Esc`/点击空白：取消选择。只允许选择己方单位。

**F20. 命令**
- **左键点击空地**（有选中单位）：**移动指令** —— 全体寻路前往，到达后集结待命。
- **A + 左键点击空地**：**攻击移动** —— 沿路遇敌自动交战，清完继续推进。
- **A + 左键点击敌方单位**：**集火该目标**。
- **左键点击卡牌**：出兵（先判卡牌矩形，再判地图，沿用现有实现顺序）。
- **选中己方主堡 + 左键点击地图**：设置集结点（F9）。
- **Esc**：退出 A 指令模式 / 取消选择。

**F21. 框选与点击的区分（关键交互）**
- `pointerdown` 记录起点；`pointerup` 时位移 **< 8px → 点击**（选单位/移动指令/设集结点），
  **≥ 8px → 框选**（只选己方单位，绘制半透明选框）。
- A 模式下点击语义自动切换为攻击移动/集火，光标与顶部提示条同步反馈（防误操作）。

**F22. 多选行为**
- 同一指令发给全部选中单位；移动/攻击移动时各单位各自寻路（路径相似 → 自然成队）。
- P1：编队快捷键（Ctrl+1~9 存编队、1~9 选编队）、双击单位选中同类（P2）。

### 5.7 自动寻路（防卡系统）

**F23. 路径计算**
- 网格 A*（64px 格，75×50=3750 格，开销可忽略）：起点/终点取单位脚底所在格；
  **终点不可走 → 自动吸附到最近可走格**再寻路。
- 寻路频率限制：每单位每 **0.3s** 最多重寻一次（性能 + 防抖动）。

**F24. 路径跟随与避让**
- 单位沿路径逐格前进（路径点插值移动）；个体间沿用**同队软分离**（SEP_MIN=30，指数收敛）。
- 多单位同指令：路径相似自然成队，窄口排队通过（软分离 + 前进方向趋同）。

**F25. 防卡机制（单位绝不能长时间卡死）**
1. **卡住检测**：移动状态但位置连续 **0.5s 几乎无位移** → 触发重寻路（冷却 0.5s）+ 小幅随机偏移破僵持；
2. **终点失效**：目标点被堵 → 吸附最近可走格，抵达最近可达处后进入 GATHER（不无限挣扎）；
3. **命令更新**：新指令/集结点变化 → 立即重寻路；
4. **被地形夹住**：软分离推不开时，沿当前路径尝试相邻可走格；
5. **兜底**：连续多次重寻仍失败 → 单位停下并提示「无法到达」（罕见，阈值可调）。

**F26. 寻路性能**
- A* 仅在命令/失效时计算；移动只是路径点插值；空间网格辅助邻域查询。
- P2：编队共享路径（一个领队 A*，跟随者沿领队路径）+ 路径简化（视线裁剪）。

### 5.8 战斗规则

**F27. 战斗系统（沿用，不重做）**
- 武器几何攻击距离、动画状态机（idle/walk/hurt/die + level/stab/recover）、长枪兵特性
  （击退/首击暴击/贴脸收枪）、剑士特性（1.5 倍加成/盾牌格挡）全部保留。
- 伤害结算与 LOD 无关：命中即正确结算；低缩放下不播精细动画但伤害/血条正确。

**F28. 攻击主堡**
- 主堡视为巨型目标（固定目标中心），单位抵近约 200px 后按武器距离正常攻击；
  受击闪白 + 顶部血条实时减少 + 飘字（P1 加碎裂粒子）。

**F29. 团战规则**
- 多单位围攻同一目标时：近战单位经软分离自动错位站位；目标被包围时后排单位自动换最近敌人（P1 优化）。
- 远程单位（P2）：射程内站定攻击、被近身后退 —— 注册表加 `range` 字段即可扩展。

### 5.9 阵营标识

**F30. 脚下阵营椭圆圈（替代阴影，所有 LOD 一致）**
- 单位脚底绘制**阵营色椭圆**：玩家蓝 `#4a9eff` / AI 红 `#e8555a`，半透明、不随身体旋转；
  替换现有 `art/spearman.ts` / `art/swordsman.ts` 的地面阴影。
- 俯瞰（LOD 0）时椭圆圈 + 阵营色小点是主要辨识手段；放大后与精细单位共存。
- 主堡有阵营色地基光晕；集结点旗帜用己方阵营色；框选/选中高亮圈用己方阵营色。

**F31. 色弱友好（P1）**
- 除颜色外增加次级辨识：单位点/椭圆可叠加小图标（如枪/剑剪影），P1 可选。

### 5.10 敌方 AI（状态机驱动）

**F32. AI 状态机（MVP 简单版）**

```
        ┌──────────── IDLE（开局 4s）────────────┐
        │                                        │
        ▼                                        │
     GATHER（集结）──────────────────────────┐   │
     · 按金币出兵（间隔 3.5~5.5s 随机）        │   │
     · 新兵集结于 AI 集结点（默认城堡前）       │   │
     · 转移条件：AI 单位数 ≥ 进攻阈值(12)      │   │
     · 或：连续 8s 金币不足出兵（等不起）       │   │
        │                                      │   │
        ▼                                      │   │
     ATTACK（全面进攻）────────────────────────┘   │
     · 全体单位攻击移动至玩家主堡（分两拨错开 3s）  │
     · 沿途自动交战                               │
     · 转移条件：AI 存活单位 < 撤退阈值(4)         │
     · 或：进攻持续超时(40s) 仍无法推进            │
        └─────────────────────────────────────────┘
        （循环直至一方主堡被摧毁）
```

**F33. AI 状态/条件数据化**
- 状态表 + 转移条件表定义在 `core/aiStateMachine.ts`（触发条件、参数、目标点计算规则），
  不写死在逻辑里 —— 调难度、加状态不改主循环。
- AI 经济与玩家同规则（20/s、开局 100）—— 公平对局，胜负靠决策与指挥。

**F34. 战术扩展架构（P2，为后续铺路）**
- `tactic` 接口：每个战术 = 一个数据化配置（目标选择规则 + 编队 + 触发条件 + 执行参数）：
  - 侦察（scout）：派 1~2 单位探图；
  - 巡逻（patrol）：沿指定路线巡逻；
  - 钳形攻势（pincer）：分两路从两侧夹击；
  - **大模型融合**：`commander.decideTactic()` 作为可插拔决策出口 —— 状态机决定"何时换战术"，
    LLM（或规则）决定"换哪个战术/执行参数"（P3）。
- 加新战术不动主循环：注册一个 tactic 配置即可。

**F35. AI 难度分级（P1）**

| 难度 | 收入倍率 | 出兵间隔 | 开局延迟 | 进攻阈值 | 决策延迟 |
|---|---|---|---|---|---|
| 简单 | 0.7× | 5~7s | 6s | 16 | 长 |
| 普通（默认） | 1.0× | 3.5~5.5s | 4s | 12 | 中 |
| 困难 | 1.3× | 2.5~4s | 2s | 8 | 短 |

### 5.11 大规模性能与 LOD（500+ 单位目标，架构先行）

**F36. LOD 三级渲染**

| 级别 | 触发缩放 | 呈现 | 成本 |
|---|---|---|---|
| LOD 0 小点 | < 0.5× | 阵营色小点(2~4px) + 椭圆圈，无血条 | 极低，2000+ 可跑 |
| LOD 1 剪影 | 0.5×~1.5× | 预烘焙静态剪影 sprite(~20px) + 阵营椭圆 + 交战迷你血条 | 低 |
| LOD 2 精细 | > 1.5× | 现有完整动画/战斗演出 | 高，同屏自然受限 |

- 整屏按缩放级别切换（避免闪烁）；500 单位时绝大多数处于 LOD 0/1。

**F37. 烘焙与池化**
- 兵种动画**离线烘焙**为帧贴图（Graphics → 离屏 RenderTexture → Texture），运行时 Sprite 播放，
  **不再每帧逐单位重绘 Graphics**（500+ 可行性的关键）。
- 单位/特效/飘字/伤害数字全部**对象池**化，避免 GC 抖动。

**F38. 空间网格 + 固定步长**
- 空间网格（128px 格）：索敌/邻域查询 O(n²) → O(邻域)。
- 逻辑固定步长 tick（30Hz）+ 渲染插值；单位 AI 分帧更新（每帧只更新 1/3）—— 为确定性/联机铺路。

**F39. 性能目标与验证**
- MVP（100~150 单位）：60fps；M2（500 单位）：中端机 60fps、低端机 30fps 可玩。
- M1 内置「+100 单位压测」按钮 + FPS 面板，验收达标再提上限。

## 9. 技术架构方案

### 9.1 分层（内核纯 TS，渲染订阅内核）

```
src/
├── main.ts                  # 入口：场景改为 GameScene
├── core/                    # ★ 纯 TS 游戏内核（不依赖 Phaser，可单测）
│   ├── config.ts            #   全部数值配置
│   ├── gameState.ts         #   金币/时间/胜负/单位上限/阵营
│   ├── economy.ts           #   金币增长/扣费
│   ├── map.ts               #   地形网格、障碍物、可通行性、A* 寻路、终点吸附
│   ├── mapLayout.ts         #   障碍物布局数据
│   ├── spatial.ts           #   空间网格索引（索敌/邻域查询）
│   ├── unitStateMachine.ts  #   单位个体状态机（GATHER/DEFEND/MOVE/ATTACK-MOVE/ATTACK/DIE）
│   ├── command.ts           #   命令队列（移动/攻击移动/集火/设集结点）→ 分发
│   ├── aiStateMachine.ts    #   ★ 敌方 AI 状态机（IDLE/GATHER/ATTACK，状态+条件数据化）
│   ├── commander.ts         #   AI 决策出口 decideTactic()（P2 战术模块/LLM 接口）
│   └── battle.ts            #   伤害结算、攻塔、胜负检测
├── units.ts                 # ★ 改造：Team='blue'|'red' 与兵种解耦；注册表加 cost/squadSize/LOD
├── scenes/
│   └── GameScene.ts         # ★ 主场景：相机(缩放/平移)、小地图、HUD、输入(点选/框选/A 指令/集结点)
├── render/
│   ├── prebake.ts           #   Graphics 动画烘焙帧贴图
│   ├── unitRenderer.ts      #   LOD 三级渲染调度
│   ├── terrainRenderer.ts   #   地形 RenderTexture
│   ├── minimap.ts           #   小地图
│   └── fxPool.ts            #   特效/飘字池
├── art/                     # 兵种/主堡/地形绘制（沿用 spearman/swordsman，阴影→阵营椭圆）
└── DemoScene.ts             # 保留：单位战斗沙盒（调试用）
```

### 9.2 关键实现点

1. **输入**：`pointerdown/up` 位移判定「点击 vs 框选」；A 键切换指令模式（光标/提示变化）；
   卡牌矩形命中优先于地图指令（沿用现有顺序）。
2. **寻路**：`core/map.ts` 提供 `findPath(from,to)` / `nearestWalkable(to)`；
   单位在 MOVE/ATTACK-MOVE 时请求路径；防卡检测在 update 内做位移监视。
3. **LOD**：整屏按 `camera.zoom` 切渲染通道；LOD 0/1 走烘焙 sprite + 空间网格，
   LOD 2 走现有 Graphics 动画（同屏受屏幕空间自然限制）。
4. **AI 状态机**：`aiStateMachine.ts` 每 tick 评估转移条件（单位数/超时/金币），
   产出指令（出兵/进攻目标点）由内核执行；状态与条件数据化，方便加战术。
5. **固定步长**：30Hz tick 内核 + 渲染插值（确定性，为联机/LLM 决策铺路）。
6. **性能验证**：M1 内置压测按钮 + FPS 面板。

### 9.3 保留不动的部分

- 战斗状态机、武器几何攻击算法、伪3D 深度排序、同队软分离、特效系统、卡牌绘制 —— 沿用。

## 12. 验收标准（MVP 可测试清单）

1. 地图 ≥4800×3200，含树林/岩石障碍物，双方主堡间 ≥2 条可行通路。

6. 左键空地 = 移动；A+左键空地 = 攻击移动（沿路遇敌交战，清完继续推进）；A+左键敌方单位 = 集火。
7. 选中己方主堡 + 左键点地图 = 设置/移动集结点（旗帜标记，新兵前往）。
8. **寻路**：命令单位穿越障碍物区域走绕行路线；反复命令到障碍物/被堵死位置，
   单位自动吸附/绕行/重寻路，**不长时间卡住**（专项测试：10 单位连续 1 分钟命令穿越障碍区无卡死）。
9. 集结时自动防御（索敌半径内自动交战，不追击出范围）；移动中被攻击会还手。
10. AI 状态机：开局 4s 后出兵集结 → 兵力 ≥12 全面进攻玩家主堡 → 兵力 <4 撤回再集结（循环）。
11. 摧毁敌方主堡 → 「胜利」；己方被摧毁 → 「失败」；可重开且状态完整重置。
12. 长枪兵/剑士特性（击退/暴击/格挡/1.5 倍加成）完整生效。
13. 性能：100~150 单位同屏 60fps；压测可加到 300+ 观察 LOD 降级。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 500+ 单位性能不足 | LOD/烘焙/池化/空间网格/分帧；压测先行，M1 达标再提上限 |

| 现有战斗系统迁移破坏 | DemoScene 保留沙盒回归；战斗逻辑原样复用，仅接状态机 |
